## 1. Retrieval Augmented Generation (RAG)

---

Retrieval augmented generation(RAG)은 4주차에서 소개했던 기술로, LLM이 답변을 내놓을 때 기억에만 의존하지 않고 인터넷 자료와 같은 외부 data source를 활용하도록 하는 기술입니다. 이러면 자연스레 LLM의 답변에서 나타나는 hallucination이 줄어들게 됩니다.

구체적으로 RAG는 다음과 같이 구현됩니다:

![https://aws.amazon.com/ko/what-is/retrieval-augmented-generation/](https://prod-files-secure.s3.us-west-2.amazonaws.com/83c75a39-3aba-4ba4-a792-7aefe4b07895/2f50e8a8-a5ea-4dae-ad17-6c6008c576f6/image.png)

<https://aws.amazon.com/ko/what-is/retrieval-augmented-generation/>

1. **사용자의 질문 입력:** 먼저 일반적인 LLM들과 똑같이 사용자의 입력을 입력 받습니다.
2. **Knowledge source로 부터 유사한 자료 추출:** 그 다음 인터넷 사이트와 같은 knowledge source로 부터 사용자의 질문과 유사한 text들을 추출합니다.
3. **추출한 자료들과 사용자 질문으로 prompt 구성:** 추출한 text와 사용자의 질문을 합쳐 최종 prompt를 완성합니다.
4. **Prompt에 대한 LLM의 답변 반환:** 완성한 prompt를 LLM에 넣어, 답변을 얻습니다.

기존의 LLM과 달라진 점은 i) knowledge source를 준비해야 하고 ii) 사용자 질문과 관련 있는 text를 knowledge source에서 찾아야 한다는 것입니다.

여기서 knowledge source는 인터넷 자료, pdf 파일 등 다양한 형태가 될 수 있습니다. 그만큼 RAG는 LLM의 기능을 확장시킬 수 있습니다.

## 2. RAG 실습

---

이번 챕터에서는 RAG를 LangChain이라는 library와 GPT API로 구현합니다. LangChain은 LLM들을 사용하면서 생기는 문제들을 해결하기 위해 나온 LLM 통합 library 중 하나입니다. 다양한 기능들이 있지만 이에 대한 자세한 설명은 6주차에서 진행할 예정이고, 이번 챕터에서는 RAG 구현법만 살펴보도록 하겠습니다.

### 2.1 구현 준비

먼저 필요한 library들을 설치하고 import 합니다:

```bash
!pip install langchain-community langchain-chroma langchain-openai bs4
```

```python
import bs4
from langchain import hub
from langchain_chroma import Chroma
from langchain_openai import ChatOpenAI
from langchain_openai import OpenAIEmbeddings
from langchain_community.document_loaders import WebBaseLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
```

그리고 LLM을 준비합니다. 이번 실습에서는 GPT를 활용합니다:

```python
llm = ChatOpenAI(model="gpt-4o-mini", api_key="...")
```

`api_key` 인자에 본인 GPT API의 API key를 입력하시면 됩니다.

### 2.2 Knowledge source 준비

이번에는 knowledge source를 준비합니다. Knowledge source로 다음 웹 사이트의 내용을 사용합니다:

[LLM Powered Autonomous Agents](https://lilianweng.github.io/posts/2023-06-23-agent/)

Knowledge source는 `beautifulsoup`라는 웹 사이트 크롤링 library와 LangChain의 `WebBaseLoader`라는 loader를 활용하여 준비합니다:

```python
loader = WebBaseLoader(
    **web_paths=("https://lilianweng.github.io/posts/2023-06-23-agent/",),**
    bs_kwargs=dict(
        parse_only=bs4.SoupStrainer(
            **class_=("post-content", "post-title", "post-header")**
        )
    ),
)
docs = loader.load()
```

`web_paths`에는 여러 개의 웹 사이트 주소를 사용하셔도 좋습니다.

여기서 주의하실 점은 `parse_only`의 `class_` 인자입니다. 이 인자는 주어진 웹사이트에 맞춰 결정된 것이기 때문에 만약 다른 웹사이트를 사용하실 계획이라면 HTML 코드로 내가 원하는 내용이 있는 HTML class들을 파악하셔서 수정하셔야 합니다.

### 2.3 Knowledge source에서 text 추출

이번에는 사용자 질문이 들어왔을 때, 이 질문 관련 있는 text들을 knowledge source로 부터 추출하는 코드를 구현합니다. 먼저 knowledge source를 다음과 같이 전처리 합니다:

```python
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000, 
    chunk_overlap=200
)
splits = text_splitter.split_documents(docs)
vectorstore = Chroma.from_documents(
    documents=splits, 
    embedding=OpenAIEmbeddings(api_key="...")
)
```

여기서도 `api_key` 인자에 본인 GPT API의 API key를 입력하셔야 합니다.

각 코드의 부분들은 다음을 수행합니다:

- **Text를 일정하기 쪼개기:** 먼저 knowledge source의 text들을 일정한 간격으로 쪼갭니다. 예를 들어 여러 장의 PDF로 구성된 문서 같은 경우, 각 장으로 쪼개는 것이 한 가지 예시가 됩니다. 좀 더 정확한 retrieving을 위해 embedding 모델에 들어가는 최소 text 크기를 줄여주기 위함입니다.
- **Embedding으로 저장:** 각 text를 하나의 embedding으로 만듭니다. 예를 들어, 각 쪼개진 text를 LLM에 넣은 후, 각 token의 embedding을 평균내는 방식으로 하나의 embedding으로 만들 수 있습니다. 여기서는 `OpenAIEmbeddings` 모델을 사용합니다.

즉, `vectorstore`는 text와 embedding의 쌍들의 모임이라고 생각하시면 됩니다.

마지막으로 어떤 질문이 던져졌을 때, 이 질문과 유사한 embedding을 가지고 있는 text를 추출하는 코드는 다음과 같습니다:

```python
retriever = vectorstore.as_retriever()
print(retriever.invoke("What is Task Decomposition?"))
```

여기서 주어진 질문은 `What is Task Decomposition?`입니다. 이 질문도 마찬가지로 embedding으로 변환하여, `vectorstore`에 있는 embedding들과 비교합니다. 여기서 비슷하다고 판단되는 embedding들을 반환하는 것을 확인할 수 있습니다.

### 2.4 최종 모델 완성

마지막으로 `retriever`를 활용하여 RAG를 마무리합니다.

먼저 다음과 같이 `retrieved_docs`를 가지고 prompt를 완성하는 부분을 구현합니다:

```python
user_msg = "What is Task Decomposition?"
retrieved_docs = retriever.invoke(user_msg)

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)
prompt = hub.pull("rlm/rag-prompt")

user_prompt = prompt.invoke({"context": format_docs(retrieved_docs), "question": user_msg})
print(user_prompt)
```

여기서 추가된 부분들은 다음과 같습니다:

- `format_docs`: 추출된 text들을 모두 concat합니다.
- `prompt`: 재료들이 주어졌을 때 하나의 prompt로 만들어주는 역할을 수행합니다. 예를 들어 여기서 사용하는 `rlm/rag-prompt`는 `context`와 `question`의 dictionary가 주어지면, 이들을 RAG 형태의 prompt로 합쳐주는 역할을 수행합니다.

마지막으로 완성된 prompt를 llm으로 넘겨주면 끝입니다:

```python
response = llm.invoke(user_prompt)
print(response.content)
```

위의 일련의 과정은 다음과 같이 chain의 형태로 쉽게 구현할 수도 있습니다:

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)
print(rag_chain.invoke(user_msg))
```

Chain은 일련의 코드를 쉽게 연결해주기 위해 LangChain에서 제공하는 기능입니다.

예를 들어 chain을 적용하기 전, 우리 코드는 `retriever.invoke` → `prompt.invoke` → `llm.invoke` → `content 뽑기`의 순서로 진행하는 것을 알 수 있습니다. 이들을 이제 `rag_chain = retriever | prompt | llm`의 형태로 `|` 연산자를 활용하여 묶게 된다면, `rag_chain.invoke` 하나의 함수로 일련의 과정을 수행할 수 있게 됩니다. 어차피 같은 invoke 함수를 사용하기 때문입니다.

그래서 이러한 chain 연산자를 활용하면 반복적인 형태의 LangChain 연산들을 줄여줄 수 있습니다.
